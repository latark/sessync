# sessync

[![tests](https://github.com/latark/sessync/actions/workflows/test.yml/badge.svg)](https://github.com/latark/sessync/actions/workflows/test.yml)
[![license: MIT](https://img.shields.io/badge/license-MIT-blue.svg)](LICENSE)
![macOS](https://img.shields.io/badge/platform-macOS-lightgrey.svg)

**Сессии Claude Code на всех ваших Mac.** Начните разговор на одном Mac, продолжите на другом
(`claude -r`) и найдите любой прошлый разговор (`sessync find`). Сессии хранятся там, где выберете вы:
Cloudflare R2, Backblaze B2, Amazon S3, любое S3-совместимое хранилище или любое хранилище, с которым
работает [rclone](https://rclone.org). Шифруются они ещё на Mac, до отправки.

[English](README.md)

![sessync: сессия с MacBook Air найдена и продолжена на Mac mini](docs/demo.gif)

Claude Code хранит сессии в `~/.claude/projects/<папка-проекта>/<id>.jsonl` только на том
компьютере, где шёл разговор, и по умолчанию удаляет их через 30 дней. Синхронизации между
компьютерами в нём нет.

## Возможности

- **Работает само.** sessync синхронизирует сессии при запуске и закрытии `claude`, а пока открыт
  хотя бы один `claude` — каждые 10 минут. Когда закрыт последний, в фоне ничего не остаётся:
  никаких служб launchd и объектов входа.
- **Продолжайте на любом Mac.** `claude -r <id>` и `/resume` видят сессии, начатые на других
  ваших Mac.
- **Передаются только новые строки.** Файл сессии только дописывается, поэтому sessync передаёт его
  так же, как [Litestream](https://litestream.io/how-it-works/) передаёт журнал базы данных. Если
  вы работаете в сессии на сотни мегабайт, при синхронизации уходят килобайты, а не весь файл.
- **Ничего не теряется.** Если сессию между синхронизациями продолжили на двух Mac, она разделяется
  так же, как при `/branch` в самом Claude Code: одна ветка остаётся в сессии, другая становится
  отдельной сессией «<заголовок> (Branch)», и обе есть в `/resume`. Сессию, открытую в `claude`,
  sessync не меняет, а `claude -r` предупредит, если открытая копия старее, чем на другом Mac.
  Обрезанный или повреждённый файл сессии никогда не заменит полный. Удалённые сессии 30 дней
  хранятся в корзине. Если за один раз удаляется больше половины файлов, синхронизация
  останавливается и ждёт вашего решения.
- **Поиск.** `sessync find слова` находит сессии, где это обсуждалось, и для каждой показывает
  команду, которой её продолжить.
- **Забыть разговор.** `sessync forget` удаляет сессию на всех Mac и в хранилище вместе с её
  промптами в истории; в течение 30 дней её можно вернуть через `sessync restore`.
- **Сессии больше не удаляются через 30 дней.** sessync увеличивает срок хранения в Claude Code
  (`cleanupPeriodDays`) до 100 лет и возвращает из хранилища сессии, которые Claude Code уже успел
  удалить.
- **Общая история промптов** (стрелка ↑) на всех Mac.
- **Разные имена пользователя на разных Mac — не помеха:** папки проектов переименовываются под
  домашнюю папку каждого Mac.

## Требования

- macOS, [Homebrew](https://brew.sh) и Claude Code для терминала.
- Хранилище: приватный бакет или любое хранилище rclone. Бесплатного тарифа Cloudflare R2 (10 ГБ,
  скачивание бесплатное) хватит на годы. Подойдут и российские S3-хранилища — Timeweb Cloud,
  Selectel, Yandex Object Storage, VK Cloud: в `sessync setup` это пункт «Другое S3-совместимое
  хранилище».

## Установка

```bash
brew install latark/tap/sessync
```

Или из git (обновление — `git pull` в этой папке):

```bash
git clone https://github.com/latark/sessync.git ~/projects/sessync
~/projects/sessync/install.sh
```

`install.sh` устанавливает rclone, ripgrep и jq, создаёт команду `sessync` в `~/.local/bin`,
добавляет два хука в `~/.claude/settings.json` и увеличивает срок хранения сессий
(`cleanupPeriodDays`). Прежний `settings.json` сохраняется рядом под именем
`settings.json.bak-sessync-…`. После установки не перемещайте папку: команда — ссылка на неё.

Затем в **обычном Терминале** (не через `!` внутри Claude: то, что вы вводите, не должно попасть в
переписку):

```bash
sessync setup     # хранилище, ключи, пароль шифрования, хуки Claude Code
sessync           # первая синхронизация
sessync export    # сохранить ключи и пароль в приложение «Пароли» (по шагам)
```

**Хранилище.** `sessync setup` предлагает Cloudflare R2, Backblaze B2, Amazon S3, любое
S3-совместимое хранилище (по его адресу, endpoint) или любое хранилище rclone — Google Drive,
Dropbox, OneDrive, SFTP, WebDAV/Nextcloud, NAS. Хранилище rclone сначала настройте командой
`rclone config`. Бакет создайте **приватный** и только для сессий, а ключ доступа — только к этому
бакету: основной ключ аккаунта открывает все ваши бакеты.

**Без пароля шифрования данные не прочитать.** Потеряете пароль — хранилище останется нечитаемым
навсегда. На первом Mac в ответ на вопрос о пароле нажмите Enter: sessync создаст случайный. Затем
выполните `sessync export`: он откроет приложение «Пароли» и проведёт по шагам. Ключи и пароль по
очереди попадут в буфер обмена — только этого Mac, без «Универсального буфера обмена» и с пометкой
«скрытое», поэтому Raycast, Alfred, Maccy и Paste их не запомнят. В конце sessync очистит буфер.
Запись из «Паролей» появится на остальных ваших устройствах через iCloud.

### Остальные Mac

1. Установите sessync так же.
2. `sessync setup` — то же хранилище, те же ключи и **тот же пароль** (возьмите их из записи в
   «Паролях»). С другим паролем sessync откажется работать и ничего не запишет в хранилище.
3. `sessync` — скачает все сессии.

## Как пользоваться

Обычно ничего делать не нужно: всё происходит само. Чтобы пересесть за другой Mac, выполните на
первом `sessync` (или просто закройте `claude`), затем запустите `claude` на втором — сессии с
первого появятся в `/resume`. Если забыли, `claude -r` на втором Mac сам скажет, что открытая копия
старее, и подскажет, как открыть свежую. Или найдите нужную сессию:

```bash
sessync find договор аренды     # сессии, где в переписке есть все эти слова
sessync find "точная фраза"
sessync find -p my-site деплой   # только в проектах, в пути которых есть my-site
sessync find                     # последние сессии во всех проектах
```

Для каждой найденной сессии видно, когда она была, в какой папке, её заголовок, фрагмент с
совпадением и готовую команду, например `cd ~/projects/my-site && claude -r 3bb6f76a-…`. Поиск идёт
только по самой переписке — вашим сообщениям и ответам Claude. Служебные вставки и вывод команд
ищутся с ключом `--raw`.
Вывод проходит маску: похожее на ключи (`sk-…`, `ghp_…`, `github_pat_…`, `AKIA…`, длинные base64 и hex, значение
после `password=`, `token=`, `secret=`) показывается как `***`; `--no-mask` её отключает.

| Команда | Что делает |
|---|---|
| `sessync` | синхронизировать сейчас |
| `sessync status` | что и когда синхронизировано, ошибки, конфликты; с `--remote` — объём в хранилище |
| `sessync find …` | поиск по всем сессиям |
| `sessync off` / `on` | выключить / включить автоматическую синхронизацию |
| `sessync conflicts` | сессии, которые на двух Mac пошли по-разному, и копии других файлов; `--delete` — удалить копии |
| `sessync trash` | удалённые сессии в корзине хранилища |
| `sessync restore <id>` | вернуть сессию из корзины; забытую — вместе с её промптами |
| `sessync forget <id>` | удалить сессию здесь, в хранилище и на других Mac вместе с её промптами; в течение 30 дней её можно вернуть через `restore`, `--now` удаляет сразу насовсем; `! sessync forget` внутри сессии удаляет её саму после выхода |
| `sessync deletes` | что удалено, если синхронизация остановилась из-за массового удаления; `--undo` — вернуть, `--apply` — удалить везде |
| `sessync setup` | хранилище (`--storage` — сменить его), ключи, пароль |
| `sessync export` | сохранить ключи и пароль в «Пароли» |
| `sessync hooks install` / `remove` | добавить / убрать хуки Claude Code |
| `sessync log` | последние строки журнала |

Интерфейс на русском, если язык системы русский, иначе на английском. Выбрать язык явно:
`LANGUAGE=ru` или `LANGUAGE=en` в `~/.config/sessync/config`.

## Строка статуса

Если в `settings.json` уже есть своя строка статуса (`statusLine`), добавьте в её вывод
`$(sessync statusline)`. Если нет, можно показывать только состояние синхронизации:

```json
"statusLine": { "type": "command", "command": "sessync statusline" }
```

Что в ней бывает:

- `сессии ↻ 13:26` (приглушённым цветом) — всё в порядке, 13:26 — время последней синхронизации.
  Жёлтым — если синхронизации не было больше 30 минут.
- `сессии: <что случилось>` (жёлтым) — ошибка.
- `сессии: конфликт N` (красным) — N копий файлов, которые менялись на двух Mac (`sessync conflicts`).
- `сессии: синхр. выкл` — автоматическая синхронизация выключена.

Об ошибке, о новой копии и о разделившейся сессии macOS ещё и один раз покажет уведомление.

## Подсказка для Claude

Чтобы Claude в любом проекте знал про архив сессий, добавьте в `~/.claude/CLAUDE.md`:

```markdown
## История сессий на всех Mac
- Сессии со всех моих Mac синхронизирует sessync (зашифрованное хранилище). Прошлые разговоры из
  любого проекта ищи через `sessync find слово …` (с `--raw` — ещё и по выводу инструментов).
  Продолжить найденную сессию — `cd <папка> && claude -r <id>`.
- Файлы сессий (`~/.claude/projects/**/*.jsonl`) и `~/.claude/history.jsonl` не клади в git и не
  публикуй: в них вся переписка, включая прочитанные файлы с ключами.
- Ключи хранилища и пароль шифрования — в Связке ключей: никогда не выводи их значения в чат и
  логи. Вводятся они только через `sessync setup` в моём терминале.
- Удалить сессию (здесь, в хранилище, на всех Mac, вместе с её промптами) — `sessync forget <id>`;
  в течение 30 дней её можно вернуть через `sessync restore <id>`, а `--now` удаляет сразу
  насовсем. Чтобы удалить текущую сессию, я набираю в ней `! sessync forget`: она удалится после
  выхода.
```

## Разные имена пользователя

Claude Code называет папку проекта по его полному пути (`/Users/ann/work/site` →
`-Users-ann-work-site`). Хранилище запоминает домашнюю папку первого Mac. На Mac с другой домашней
папкой (`/Users/bob`) sessync переименовывает папки проектов при получении и отправке, а также
исправляет пути проектов в истории промптов. Сама переписка не меняется: в старых сообщениях
останется прежний путь, продолжать сессию это не мешает. Проекты вне домашней папки должны лежать
по одному и тому же пути на всех Mac. Очень длинные пути, которые Claude Code сокращает с помощью
хэша, переименовать нельзя.

## Корзина

Сессия, удалённая на любом Mac, сначала копируется в папку `trash/<дата>/` того же хранилища — без
скачивания и тоже в зашифрованном виде — и только потом удаляется. Через 30 дней копия удаляется
сама (срок задаёт настройка `TRASH_DAYS=…`).

```bash
sessync trash               # что лежит в корзине и когда удалено
sessync restore 3bb6f76a    # вернуть сессию вместе с вложениями (id или часть пути)
sessync                     # сессия вернётся в хранилище и на другие Mac
```

Сессии, удалённые через `sessync forget`, тоже лежат в корзине с пометкой «забыта»; `sessync restore`
возвращает и их промпты.

Старые версии сессий отдельно не хранятся: файл сессии только дописывается, поэтому каждая новая
версия целиком содержит предыдущую.

## Как посмотреть и удалить сессии

- `claude --resume`: `Ctrl+A` — сессии всех проектов, пробел — просмотр, `Ctrl+R` — переименовать.
- [Agent Sessions](https://github.com/jazzyalex/agent-sessions) — приложение для macOS, в котором
  удобно читать старые разговоры целиком. Сами сессии оно не меняет. На первом экране выключите
  «Enable Quota Meter», если вам не нужны лимиты (иначе приложение будет читать токен входа Claude
  Code из Связки ключей). И не включайте его tmux-зонд: он запускает `claude` в своей папке, и
  sessync разошлёт эти служебные сессии на все Mac.
- Удалить проект целиком — `claude purge <папка>` (команда Claude Code). Проект удалится и на
  других Mac, а копия 30 дней пролежит в корзине.
- Удалить одну сессию везде — например, открытую ради одного короткого вопроса:
  `sessync forget <id>` (id есть в `sessync find`; хватит первых 8 символов, если с них не
  начинается другая сессия). Команда сначала спросит; `-y` — без вопроса. Изнутри самой сессии
  наберите `! sessync forget`: она удалится, когда вы из неё выйдете (`/exit`), а до тех пор не
  синхронизируется. Передумали — `sessync forget --cancel <id>`. Что удаляется:
  - переписка и её папка (субагенты, вложения), здесь и в хранилище;
  - её промпты в истории (↑) вместе со вставленным в них текстом, в том числе в файле истории этого
    Mac в хранилище;
  - что Claude Code держит о ней вне папки проектов: файлы и папки с её id в имени (например,
    `session-env`, `file-history`, `todos`, `debug`, `security`) и её временная папка
    `/tmp/claude-<uid>/<проект>/<id>`;
  - её текст в индексе поиска.

  Остальные Mac делают то же при своей следующей синхронизации (если там она открыта — после
  закрытия). Переписка и её промпты 30 дней (`TRASH_DAYS`) лежат в корзине хранилища:
  `sessync restore <id>` вернёт их на любом Mac, и тогда сессия вернётся и на остальные Mac; через
  30 дней они удаляются насовсем. Возвращайте забытую сессию только через `sessync restore`: её
  метка остаётся в хранилище навсегда, даже после очистки корзины, и пока она есть, каждый Mac
  удаляет файл этой сессии, где бы он ни появился, мимо корзины — копия, возвращённая вручную или из
  Time Machine, исчезнет при ближайшей синхронизации. Служебные файлы Claude Code о ней (точки
  `/rewind`, временная папка) не возвращаются. Для разговора, от которого не должно остаться копий,
  — `sessync forget <id> --now`: мимо корзины, и её прежние копии там тоже удаляются.

  Что остаётся: `memory/` проекта (у каждого Mac своя), её ветки «… (Branch)» — это отдельные
  сессии, их удаляют по их id, — то, что за время разговора ушло в Anthropic, копии в ваших
  резервных копиях (Time Machine) и старые версии у провайдера, если бакет их хранит
  (версионирование; Backblaze B2 хранит все версии, пока в правилах жизненного цикла не выбрано
  «хранить только последнюю»). Её промпты в файле истории Mac, который больше не синхронизируется,
  остаются в хранилище в зашифрованном виде: переписать свой файл может только тот Mac, а
  показывать их не будет ни один.
- Вручную — удалите файл `<id>.jsonl` и папку `<id>/` рядом с ним (в ней субагенты и вложения).
  Удаление дойдёт до других Mac, и корзина 30 дней хранит копию, но её промпты в истории и
  служебные файлы Claude Code о ней останутся.

## Безопасность

Коротко: содержимое и имена файлов шифруются на вашем Mac (rclone crypt), хранилище видит только
зашифрованные объекты, их размеры и время загрузки. Ключи и пароль хранятся в Связке ключей. Всё,
что sessync записывает на диск, доступно только вашему пользователю. Подробности и модель угроз —
в [SECURITY.md](SECURITY.md) (на английском).

## Ограничения

- Пока только macOS. Следующим будет Linux.
- Синхронизация не мгновенная: при запуске и закрытии сессии и каждые 10 минут. Перед тем как
  пересесть за другой Mac, выполните `sessync`.
- Если продолжать одну сессию на двух Mac одновременно, она разделится на две сессии. Ничего не
  потеряется, но разговор окажется в двух местах.
- Удаление на одном Mac доходит до остальных (копия 30 дней хранится в корзине; после
  `sessync forget --now` копии нет).
- Синхронизируются только сессии и история промптов. Настройки, плагины, навыки, точки отката
  `/rewind` и папки `memory/` — нет: их удобно держать в git-репозитории вашей папки `~/.claude`.
- sessync рассчитывает на то, что Claude Code только дописывает файлы сессий. Если это изменится,
  sessync придётся переделывать.

## Если что-то не так

| Что видно в строке статуса или в `sessync status` | Что делать |
|---|---|
| `не настроено (sessync setup)` | выполните `sessync setup` в Терминале |
| `нет доступа к хранилищу …` | проверьте интернет, имя бакета, ключи (`sessync setup`) и баланс у провайдера |
| `пароль шифрования не тот, что на других Mac` | выполните `sessync setup` и введите пароль из «Паролей» |
| `settings.json не читается` | в `~/.claude/settings.json` ошибка; `jq . ~/.claude/settings.json` покажет, где |
| `не завершилась (код …)` | чаще всего виновата сеть; sessync повторит сам, подробности — `sessync log` |
| `остановлено: слишком много удалений` | `sessync deletes` покажет, что и где удалено; если по ошибке — `--undo`, если намеренно — `--apply` |
| `хранилище в формате новее этой версии` | на другом Mac более новый sessync — обновите этот (в 3.0 формат поменялся, так что на всех Mac нужна 3.0 или новее) |
| `сессии ↻ …` жёлтым | давно не было синхронизации: посмотрите `sessync status`, возможно, нет сети |

Журнал — `~/.local/state/sessync/sync.log`.

## Удаление

В папке репозитория:

```bash
./uninstall.sh            # убрать хуки и команду; ключи, пароль и данные останутся
./uninstall.sh --purge    # ещё и удалить ключи и пароль из Связки ключей, локальное состояние, индекс поиска
```

Если ставили через Homebrew: `$(brew --prefix sessync)/libexec/uninstall.sh` (можно с `--purge`),
затем `brew uninstall sessync`.

Данные в хранилище остаются — если они больше не нужны, удалите бакет в панели провайдера. Срок
хранения сессий (`cleanupPeriodDays`) тоже остаётся 100 лет: поставьте 30, если хотите, чтобы старые
сессии снова удалялись.

## Как устроено

- Всё в хранилище зашифровано `rclone crypt` — и содержимое, и имена. Синхронизацией занимается
  `lib/engine.py` (python3 без зависимостей, поверх rclone). Папки `memory/` не синхронизируются.
- **Файлы сессий** (`*.jsonl`) только дописываются, поэтому передаются как журнал. В хранилище у
  сессии есть **основа** — полная копия на какой-то момент — и **хвосты**: объекты со строками,
  дописанными после неё. Отправляются только новые целые строки. Другой Mac скачивает только новые
  хвосты и дописывает их в конец своего файла или читает нужный кусок из середины основы
  (зашифрованный файл можно читать с любого места).

  ```
  Mac A       session.jsonl   ████████████████████████▒▒░
  хранилище                   [ основа 9,4 МБ         ][хвост][хвост]   ← каждая синхронизация добавляет хвост
  Mac B       session.jsonl   ████████████████████████▒   + новый хвост → тот же файл байт в байт
  ```
- **Уплотнение** выполняет Mac, который дописал сессию последним. Если сессия час не менялась, её
  хвосты сворачиваются в один. Если хвостов набралось 48, они сворачиваются, даже пока сессия идёт.
  Если хвосты по объёму догнали основу, вся сессия отправляется как новая основа. Каждая новая
  основа хотя бы вдвое больше прежней, поэтому за всё время на сессию отправляется не больше двух
  её размеров.
- **Вложения** (вывод команд, картинки, копии конфликтов) записываются один раз и передаются
  целиком. Символьные ссылки (субагенты) передаются как ссылки.
- **Сессию продолжили на двух Mac** между синхронизациями — с какой-то строки она пошла двумя
  путями. Общее начало остаётся; одно продолжение остаётся в сессии — то, где есть переписка, затем
  то, о котором уже решили раньше, затем более длинное, — а другое становится отдельной сессией, как
  при `/branch`: те же строки с новым id сессии и заголовок «<заголовок> (Branch)». Id ветки
  вычисляется из сессии и строки, где версии расходятся, поэтому все Mac создают одну и ту же ветку,
  а Mac, чья ветка уже стала отдельной сессией, дописывает в неё свои следующие строки. Продолжение
  только из служебных строк Claude Code (сессию открыли и закрыли) отбрасывается. Почему не
  склеивать обе версии в один файл, как делают некоторые инструменты: Claude Code и сам хранит ветки
  в одном файле (после `/rewind`), но показывает только одну из них — другую не открыть ни из
  `/resume`, ни через `claude -r`. Остальные файлы, менявшиеся на двух Mac: под именем остаётся
  версия большего размера, другая — рядом как `<имя>.conflict1`; файл сессии, ставший короче, — тоже
  конфликт.
- **Открытые сессии.** Claude Code читает файл сессии при открытии, а дальше только дописывает его.
  Поэтому файл сессии, открытой в `claude` на этом Mac, sessync не меняет (узнаёт о них от своих
  хуков и из реестра Claude Code `~/.claude/sessions/`): строки с другого Mac ждут, пока она
  закроется. При `claude -r` хук старта сверяет с хранилищем только эту сессию — около секунды, их
  ждёт первый ответ Claude — и предупреждает, если у неё есть строки с другого Mac, которых в этом
  окне нет; полная синхронизация идёт в фоне. Отключить проверку — `RESUME_CHECK=off` в настройках.
- **Удаление.** Удалённое на этом Mac сначала копируется в корзину. Если сессию удалили на другом
  Mac, а здесь она открыта, здесь она удалится после закрытия.
- **Забыть сессию** (`sessync forget`). Когда сессия закрыта, Mac кладёт в хранилище метку с её id
  и переносит сессию и её промпты в корзину; каждый Mac, встретив метку, удаляет свою копию и
  убирает её промпты из истории и, пока метка есть, эту сессию не отправляет и не получает.
  Метка остаётся навсегда; убирает её `sessync restore`. С `--now` это единственное удаление мимо
  корзины.
- **История промптов.** У каждого Mac в хранилище свой файл (имя Mac и начало его аппаратного UUID).
  Пишет в него только этот Mac — дописывает свои новые промпты, остальные его только получают. На
  каждом Mac все эти файлы объединяются построчно, без повторов. Когда `sessync forget` убирает из
  файла промпты сессии, Mac отправляет файл целиком, и остальные берут новую версию.
- **Формат** хранилища записан в контрольном файле. Если формат новее, чем знает установленная
  версия, она останавливается, а не пишет по-старому. Формат 3 появился вместе с `sessync forget`:
  версия 2.x вернула бы забытые промпты, поэтому она останавливается.
- **Файлы на этом Mac:** состояние — `~/.local/state/sessync/` (журнал, метки для строки статуса,
  состояние движка, сессии, ждущие удаления), настройки — `~/.config/sessync/config`, индекс
  поиска — `~/.cache/sessync/find`.
- **Тесты** — `tests/run.sh`: несколько «Mac» и локальная папка вместо хранилища. Связку ключей,
  буфер обмена и настоящий `~/.claude` тесты не трогают.
